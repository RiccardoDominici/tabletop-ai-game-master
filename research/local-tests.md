# Local STT and fast narrator LLM on Apple M1 16 GB

Date: 2026-11-01. Machine: Apple M1, 16 GB unified memory, macOS 25.1.0.
Other processes were running during the tests (a Docker VM, Claude, iTerm, other agents; load average 3 to 5), so the timings are not from an idle machine.
Every number below comes from the JSON and log files in `outputs/` and `logs/`. The tables are generated by `scripts/make_tables.py`.

## Verdict

- **STT (Whisper large-v3-turbo, MLX): usable locally.** 25 s of audio transcribes in 2.37 s warm (real-time factor 0.09) with about 2.5 GB peak memory. Italian WER on the 28 TTS clips is 0.028, with an exact match on 14 of 28 files. Most remaining errors are proper names (Kara, Brunvalle, Vallestorta). These are clean TTS recordings, not people talking over each other in a room, so the real error rate will be higher. Not tested on real speech.
- **Fast narrator (LFM2.5-2.6B, 4-bit): not usable as configured.** Speed is fine only with reasoning switched off: first token about 1.1 s, about 33 tokens/s, about 5 s per narration. But that output copies the scene and states Mirto's private theft in 5 of 5 runs at the recommended temperature, and in 3 of 5 at temperature 0.7. The PRIVATE rule in the system prompt made no difference (control without the rule: 5 of 5). With default reasoning the model writes about 1,600 reasoning tokens first, and the visible narration arrives after 49 s median.
- **JSON parsing:** the content is right, but the output is wrapped in markdown fences (0 of 3 strict-valid, 3 of 3 after stripping the fences). With reasoning off, the target is wrong in 3 of 3 runs (`porta` instead of `sotto il tavolo`).
- **On the OpenRouter finding:** the LFM2.5-2.6B chat template always opens a `<think>` block, and the model card says it "always thinks before it answers". Prefilling an empty think block does switch the reasoning off (measured below). So the blocker is output quality and privacy, not only reasoning length.

## Test 1: STT and TTS intelligibility

### Method

- **Input:** the 28 files in `tts-tests/manifest_all.json`. That is 3 narrator lines, 4 NPC lines, 1 tricky narrator line and 20 voice-sweep files (10 voices, 2 lines each). Each file was resampled to 16 kHz mono.
- **Transcription:** `mlx_whisper.transcribe(audio, language="it")` with default decoding settings.
- **WER:** lowercase, apostrophes and hyphens become spaces, other punctuation is removed, then word-level Levenshtein against the source text. CER is the same at character level, with spaces removed.
- **Caveat:** the WER mixes two things: TTS pronunciation and Whisper's own errors on clean audio. It is a proxy for intelligibility, not a pure STT score.
- **Latency:** each model runs in a fresh process. "Cold load" is the `ModelHolder.get_model` time (float16, the same dtype as `transcribe`). The first call after loading includes Metal warm-up. "Warm" is the median of 3 runs. Clips: `stt_clip_5s` (5.0 s) and `narr_bram_02_combattimento` (25.3 s). Audio is loaded before timing, so WAV decoding is not counted. Peak memory is from `/usr/bin/time -l`.
- **Limit:** the cold load happened while the OS page cache still held the weights (they had been read minutes before), so a cold start after a reboot will be slower. That was not measured.

**Reading the results:**

- With turbo, all ten voices score identically on the tricky line (WER 0.059, from "Kara" becoming "Cara"). Italian normally writes that sound as "C", so the error is orthographic and not necessarily a pronunciation failure.
- "Vallestorta" becomes "Vallestarte" with turbo for vincent and lucian, and not for nadine or tabitha. Whisper-small misreads the same name in three voices. The name is hard, and the errors do not follow one voice consistently.
- Whisper-small adds errors that are not about the TTS at all, such as "appenentrati" (missing space) and "hoste" for "oste". Its per-voice spread therefore does not rank the voices reliably.

## Test 2: fast narrator LLM (LFM2.5-2.6B, 4-bit)

### Method

- **Model:** `LiquidAI/LFM2.5-2.6B-MLX-4bit`, affine 4-bit with group size 64, run with mlx-lm 0.32.2.
- **Sampling:** taken from the model card, temperature 0.1, top_k 50, repetition_penalty 1.1. The temperature-0.7 run checks variability.
- **Two modes:**
  - `default`: the chat template as shipped. It ends the prompt with `<think>`, so the model reasons first.
  - `nothink`: the same prompt plus `\n\n</think>\n\n`, which closes the think block empty. I checked that the token IDs equal the template's IDs plus that suffix.
- **Narration prompt (Italian):** the system prompt sets the narrator style (epic-ironic, short sentences, second-person plural, present tense, at most 5 sentences, Italian only). Its PRIVATE rule says private actions must not be described or hinted at. The user message gives the scene (Taverna del Corvo Zoppo, Brunvalle, Ostilia, the hooded stranger, rain, the barred back door) and three actions. Mirto's action is marked "PRIVATA, solo per il master".
- **Control:** the same prompt without the PRIVATE rule.
- **Leak check:** a keyword filter first (mirto, borsa, sfil, ruba, furt, tasca, ladr, scipp). Then every visible answer was read by hand, and the manual judgement is what is reported. The filter gave one false positive (see the leak table).
- **Latency:** TTFT is the time to the first generated token, including prompt processing. Decode speed is (tokens minus 1) divided by the time between the first and last token. For default mode, "visible TTFT" is the time to the first character after `</think>`.
- **Matrix:** narration in default mode (5 runs), nothink with the rule (5 runs), nothink with temperature 0.7 (5 runs), nothink without the rule (5 runs, control), and JSON parsing in each mode (3 runs). Each run is a fresh process under `/usr/bin/time -l`.
- **Overlap:** another process created the `Kokoro-82M-bf16` cache entry at 23:16, during the matrix run. Decode speed stayed at 31 to 34 tokens/s throughout, so the effect looks negligible, but it is a possible contamination.

## Limits

- The WER uses clean TTS recordings. It says nothing about real speech in a noisy room. A test with real recordings is needed before relying on the STT number.
- Only one quantization of the LLM was measured (4-bit, per the orchestrator's instruction). The 8-bit build and the non-thinking LFM2.5-1.2B-Instruct were not measured. The 1.2B model is the obvious next candidate, because its template does not force a think block.
- The leak judgement is one reviewer's reading of the 20 narration outputs (4 configurations x 5 runs), with a keyword filter as a cross-check.
- Sentence counts use punctuation, so they are approximate.
- Italian quality was judged from the outputs shown above and in `outputs/llm/verbatim/`, not from a fluency score or a native-speaker review.
- Cold-start load times after a reboot were not measured.
