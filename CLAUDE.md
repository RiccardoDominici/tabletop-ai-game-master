# Rules for anyone working on Tabletop AI Game Master

These rules apply to anyone (people or agents) who changes the repo. Read them before your first change.

## What the project is, in one line

Tabletop AI Game Master is a **framework**: it generates endless D&D campaigns to play in person with an AI narrator.
It is not a campaign. A campaign is an *output* of the framework (`campagne/<id>/`), generated by the Preparer
from a brief. Judge every change this way: does it work for any campaign, or only for the one that
inspired it? If a special case seems needed for a single campaign, look for the general rule instead.

## Documentation: update it together with the code

- Every change updates, in the same commit, the documentation it affects: `README.md`, the pages of
  `docs/guide/` (the step-by-step user guide) and the project `docs/*.md` files that describe the changed
  behaviour (`docs/prove.md`, `docs/strati.md`, `docs/audio.md`, `docs/architettura.md`, …). The
  internal design documents under `docs/` (not `docs/guide/`) are written in English, like the rest of the documentation.
- A new feature or option is not finished until it appears in the guide, with the real command.
  Do not write commands or flags without checking them in the code or in the scripts.
- A change that makes a guide page false is a bug, even if the code works.

## Secrets: check before every push

Keys and tokens never go into the repo. Before every `git push` (and before making the repo public)
run this check from the root and stop if it finds anything:

```bash
# 1. File che non devono essere tracciati (il solo .env.example è ammesso)
git ls-files | grep -E '(^|/)\.env(\.[^e][^/]*)?$|^logs/|^cache/|(^|/)\.venv/|__pycache__|node_modules/' && echo "TROVATO: file vietati"

# 2. Pattern di chiavi e token nel contenuto dei file tracciati
git grep -nE 'sk-ant-|sk-or-v1|hf_[A-Za-z0-9]{10,}|ghp_[A-Za-z0-9]{10,}|gho_[A-Za-z0-9]{10,}|[A-Z_]*_API_KEY=[^[:space:]]+' -- ':!.env.example' && echo "TROVATO: pattern di chiave"

# 3. Regole ricavate da un manuale non libero: il set non va nel repository
# (un set da un manuale libero, es. SRD CC-BY, può stare nel repo: si fermano solo i set con libera: false)
for f in campagne/*/regole/regole.yaml; do
  [ -e "$f" ] || continue
  grep -qE '^\s*libera:\s*false' "$f" || continue
  git ls-files "$(dirname "$f")" | grep . && echo "TROVATO: file tracciati di un set non libero in $(dirname "$f")"
done
git check-ignore -q manuali/x.pdf || echo "ATTENZIONE: manuali/ non e' nel .gitignore"

# 4. Token del master copiati dai log (compaiono come ?token=… nel log del server)
for t in $(grep -ohE 'token=[A-Za-z0-9_-]{12,}' logs/*.out logs/*.jsonl logs/*/*.out 2>/dev/null | cut -d= -f2 | sort -u); do git grep -nF -e "$t" -- ':!*.spec.ts' ':!*.test.ts' && echo "TROVATO: token del master"; done
# (the fixed tokens of test instances live in *.spec.ts / *.test.ts on purpose and also show up in the test logs)
```

The script above is kept as it is, with its comments and messages in Italian. In short: check 1 looks for
files that must not be tracked (only `.env.example` is allowed); check 2 looks for key and token patterns in
tracked files; check 3 stops rule sets taken from a non-free manual (the ones with `libera: false`) from
entering the repository, and warns if `manuali/` is not in `.gitignore`; check 4 looks for Game Master
tokens copied from the logs. Each line it prints starting with "TROVATO" ("FOUND") or "ATTENZIONE"
("WARNING") is a finding.

Check 4 applies only if logs exist; token values are never printed in the terminal or in commit
messages. If a secret has already ended up in a commit, deleting it is not enough: it must be revoked and
the commit rewritten before publishing.

Key values are read from: the environment variable, then `.env` at the root (outside git), then the
configured fallback file (`apps/server/src/llm/chiavi.ts`, `strumenti/chiavi.py`). The logs show only the
source and the length. Never add a `console.log` or a `print` of a key or token value.

## Ports: 4610 and 4611 belong to the real game

- `4610` is the server of the real game; `4611` is the local Qwen voice service.
- Trial runs, tests and development instances use `TAGM_PORTA` with another port (e.g. `4710`),
  and logs in `logs/porta-<porta>/`. Do not start, stop or restart anything on 4610 or 4611 for a trial run.
- Automated tests must never open 4610 or 4611. A test that needs a server uses a free port
  chosen by the test, or `TAGM_PORTA`.
- `scripts/arresto.sh` and `scripts/avvio.sh` stop and start only the port you ask for: do not use them on
  a game in progress unless Riccardo has asked for it.

## Commits: explain the why

- The message says why the change is needed, not only what changes. The first line is the *what* in
  short; the body explains the *why* (the problem, the choice, what was rejected and why).
- One commit = one verified unit. Before committing, the relevant tests pass (`npm test`,
  `python3 -m pytest -q <file>`).
- Commit messages in English from now on (the project is language-independent; older history is in Italian).
- New code comments and log messages in English. Existing Italian identifiers, comments and log lines stay until the planned code-translation phase (Riccardo's choice); don't mix languages inside one function.

## Framework principle

- The code generates campaigns: it does not contain the content of a specific campaign. The names, places
  and characters of `campagne/<id>/` stay in the campaign's files, not in the code, in generic tests or in
  system prompts.
- Test fixtures are invented and generic; real campaigns serve as examples, not as a source for tests
  that depend on them. When a rule changes, the test that proves it lives in a minimal fixture, not in the
  campaign.
- The Preparer's skills and prompts describe general rules (format, validation, sessions), not the
  plot of a story.

## Other rules

- No monolithic files: small modules with clear responsibilities.
- Adequate logging: important decisions and errors yes, personal data or secrets no.
- Before a non-trivial change, read `docs/architettura.md` and the `docs/*.md` files of the subsystem.
